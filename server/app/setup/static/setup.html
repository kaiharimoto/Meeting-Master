Who writes the notes

Ollama runs on this machine and needs no account or internet — that is the default, and the fallback. Claude writes better notes for long or difficult meetings, and this machine can reach it even when the work network cannot.

Sign in once on this machine by running claude login in a terminal. It uses your existing Claude subscription — no API key. If a meeting fails with a limit or sign-in error, switch back to Ollama and the notes still get written.

AI models

Which local models this server uses. Changing the summary model requires pulling it in Ollama first (Overview tab). These settings apply to Ollama; Claude ignores them.

Hitting context/VRAM errors? LOWER the context window (e.g. 16384) — long meetings are automatically summarized in chunks that fit, so a smaller window is reliable, not lossy. The URL may point at any Ollama-compatible server on this machine or your network.

Fit to your GPU

What fills graphics memory is the model's weights plus its KV cache, and the cache cost per token comes from the model's own layer and head counts — not from its parameter count. So this reads those numbers off each installed model and works out the largest context window that actually fits your card.

A quantized KV cache needs both OLLAMA_FLASH_ATTENTION=1 and OLLAMA_KV_CACHE_TYPE set in Ollama's own environment (a Windows user variable, then restart Ollama). Without them Ollama keeps using f16 and these numbers will be optimistic.

Live suggestions (during the meeting)

While the laptop is recording with the live transcript on, it asks this server every so often for questions it heard being answered and key insights worth carrying forward. The note-taker approves them one at a time in a side panel. Everything about the loop is configured here — the laptop reads these settings at the start of each meeting.

Suggestions arriving late is the usual complaint, and the cause is almost always a big summary model answering slower than the interval. Fix it by naming a smaller live model above, or by raising the interval. Keeping the model loaded avoids paying for a cold start on every ask.
